## 发现问题（已登记 feature_list）

- **p32-13（P1，本轮新发现，确定性复现×2）**：~~工作权泄漏~~ **定性更正（修复阶段实证）**：并非泄漏，而是 REST 修订路径（编辑/回退/Agent 应用）的**同步派生刷新链**（摘要重算等 LLM 调用）把 HTTP 响应与项目所有权阻塞十几分钟（实测 restore 挂起 >5min、busy 持续 >4min）——数据早已落库但 UI 呈现「等待内容处理完成」假死锁，即体验报告 #6 互锁现象与 #2「段落应用等待约 8 分钟」的共同根源。**已修复**（c115248）：REST 接线改用异步刷新 + DerivedWriteBoundary 版本门，响应立即返回、所有权立即释放，异步失败发事件不再静默。
- **p32-11**：全书质量评价结果不持久化（无 GET），切 tab/刷新即"尚未评价"（报告 #7 复现）。**已修复**（ad9e444）：评价历史落库 + GET 读回 + 前端挂载加载。
- **p32-12**：所有权占用与版本冲突同为 409，统一显示"章节已被更新，请重新确认"误导重试。**已修复**（673c020）：code=WORK_OWNERSHIP_CONFLICT + 前端分级文案。
- 体验类：章节卡 HTTP 缓存导致普通 F5 读旧数据（硬刷新才更新）——**已修复**（73da06f，p32-14：/api no-store + 前端 cache:'no-store'）；截图 CDP 超时（与报告环境一致，未修）。
