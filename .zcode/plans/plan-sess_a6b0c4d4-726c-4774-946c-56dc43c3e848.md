# 情节质量提升方案：打通结构化大纲管道 + 反套路 Prompt

## 根因总结

情节质量卡在 7/10 的三处数据管道断裂：
1. **`parseOutline` 压扁结构**：Plotter 生成了"场景节拍+爽点+人物"，但正则 `(.+)` 一把吞进 `synopsis` 扁平字符串
2. **`writingNotes` 从未接线**：设计用于"爽点/节奏"的字段，全代码库无人写入
3. **`buildTaskSection` 降维**：传给 ChapterWriter 的"本章任务"只有两行扁平文本，节拍/爽点信号丢失

叠加 prompt 层面的反套路指导过弱（Plotter 正例本身是套路、ChapterWriter 零反套路约束）。

## 5 个改动点

### Fix 1：ChapterSynopsis 扩展结构化字段
**文件：** `domain/ChapterSynopsis.java` + SQLite schema + repository

新增字段：
- `beats`（String，分号分隔的场景节拍）
- `climax`（String，本章爽点设计）
- `cast`（String，出场人物）

### Fix 2：parseOutline 精细化解析
**文件：** `agent/PlotterAgent.java`

从 LLM 输出的 `第X章 标题：场景节拍。爽点：Y。人物：Z` 中：
- 正则拆分出 `beats`（冒号后到"爽点："之间的部分）
- 拆分出 `climax`（"爽点："后到"人物："之间）
- 拆分出 `cast`（"人物："后的部分）
- `synopsis` 只保留场景节拍核心描述

### Fix 3：buildTaskSection 结构化输出
**文件：** `memory/ContextAssembler.java`

把 `【本章任务】` 从一行扁平 `内容：xxx` 改为结构化分段：
```
【本章任务】
章节：第1章 XXX
场景节拍：A→B→C→D
爽点：XXX
出场人物：甲、乙
```

### Fix 4：plotting.st 反套路强化
**文件：** `prompts/plotting.st`

- 删除套路正例（"被嘲讽→觉醒→震惊全场"）
- 增加反套路黑名单："禁止：坠崖得宝/废柴觉醒被嘲/大比打脸/秘境捡漏"
- 增加创新爽点类型："信息差/反预期/智斗/情感反转/规则利用"
- 要求每章爽点必须绑定世界观的某个独特设定

### Fix 5：chapter-writing.st 四段式细化 + 反套路
**文件：** `prompts/chapter-writing.st`

- 四段式加字数比例：开场钩子15%→冲突升级40%→高潮/爽点30%→悬念结尾15%
- 增加"将【本章任务】的场景节拍逐一展开为具体场景"的指引
- 增加反套路条款："禁止使用以下套路桥段：坠崖得宝、灵根测试被嘲后打脸..."
- 增加"爽点执行技巧"：铺垫-压抑-释放三拍、信息差揭示

## 验证
新建项目写 3 章，跑 DeepSeek 质量评价，检查 plot 分数是否从 7→9。
