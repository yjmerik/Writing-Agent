# Spec: E2E 遗留问题定点修复

## 背景与动机
用户针对 continued-e2e-20260921.md 要求：只修复遗留问题，不扩展架构；LLM 本身输出不稳定的问题登记即可；完成特性并本地合并。

## 目标
1. 修复守卫缺少已有前文证据的问题，沿用现有仓库查询和检查流程。
2. 修复真典、实体提取失败被记为完成的问题，沿用现有错误和恢复流程。
3. 核对伏笔解析和卷末检查的范围，只修复确定的解析/时间范围缺陷。

## 非目标
不增加 Agent、服务、数据库表、检索架构、重试机制；不调模型、不通过多次采样追逐绿色结果，不人工放行旧稿，不更新 golden。原优化方案中不属于本报告的待办不在本轮范围。

## 验收标准
- 代码缺陷先由 failing test 复现，再以最小改动修复。
- 每个 feature 单独分支、编译/全量/专项验证、合并 main 及合并后验证。
- 使用已保存真实失败样本及确定性测试验证修复，保留原真实 E2E 失败报告。
- 按用户本次指定口径，将模型截断/回答缺项及文学判断不稳定登记为遗留，不用它们无限阻塞代码修复和合并；不声称真实文学质量验收已通过。
- 改变检查输入后旧录制可能指纹不匹配，如实记录；本轮不重新真实录制或 bless。真实长篇/艺术验收仍归 NCS-058。

## 影响面
既有 ConsistencyGuard、提取 Agent、ChapterPostProcessor 及伏笔解析/检查；无新架构，无 schema 变更。每项按当前 feature 的局部测试和证据单独闭环。

## Feature 拆分
NCS-033：补足已有前文检查依据；NCS-063：无效真典提取不得成功；NCS-064：实体提取错误不得被忽略；NCS-061/062：核对并修复/验证伏笔时间信息和未来信息排除。独立问题仍逐项推进。

## 风险与备选方案
模型即使收到正确上下文仍可能误判或输出截断；此为模型遗留，不用伪造成功数据、放宽质量门槛或自动人工批准掩盖。完成记录仅证明本次代码修复范围。
