# Agent 架构优化方案 V3：作者可控 + 对话丰富化

## 核心设计原则

1. **作者可控制** — 所有写作参数（对话密度/爽点轮换/引用素材等）通过 `WritingPreferences` 域对象存储，作者随时修改
2. **自然语言交互** — 作者通过与 `WritingPreferencesAgent` 对话调整参数，无需写代码/JSON
3. **通用组件** — 不绑定玄幻修仙，适配任何小说类型

---

## 架构总览

```
WritingPreferences (持久化，每项目一份)
  ├── dialogueDensity: 0.35        // 对话占比目标
  ├── climaxRotation: true         // 是否轮换爽点类型
  ├── characterVoiceProfile: {...} // 每个角色的说话风格配置
  └── knowledgeSources: [...]      // 引用素材来源

WritingPreferencesAgent (交互式 Agent)
  ├── 作者输入："对话太少了，增加到40%"
  ├── → 解析意图 → 更新 WritingPreferences
  └── → 回复确认："已更新，下章开始对话占比目标设为 40%"

ContextAssembler (读取 WritingPreferences → 生成约束)
  └── buildDialogueConstraints()
  └── buildCharacterVoiceSection()
  └── buildKnowledgeQuoteSection()
```

## 一、WritingPreferences 域对象（新增）

```java
public class WritingPreferences {
    private String id, projectId;
    
    // 对话控制
    private double dialogueDensity;         // 0.0-1.0，默认 0.35
    private boolean enableDialogueEnforcement; // 默认 true
    
    // 爽点控制
    private boolean enableClimaxRotation;   // 默认 true
    private String[] excludedClimaxTypes;   // 作者禁用某些类型
    
    // 角色声音
    private boolean enableCharacterVoice;   // 默认 true
    
    // 引用素材
    private boolean enableKnowledgeQuotes;  // 默认 true
    private String[] preferredQuoteSources; // 作者指定引用来源
    
    // 过渡控制
    private boolean preventTransitionOverlap; // 默认 true
    
    // 元数据
    private Instant updatedAt;
}
```

持久化：SQLite 表 `writing_preferences` + NovelRepository SPI 新增方法。

**前端 API：**
- `GET /api/projects/{id}/preferences` — 获取当前配置
- `PUT /api/projects/{id}/preferences` — 直接修改 JSON
- `POST /api/projects/{id}/preferences/chat` — 自然语言交互（调 Agent）

## 二、WritingPreferencesAgent（交互式 Agent，核心新增）

### 工作方式

```
作者 → "对话太少了，增加到40%"
  ↓
WritingPreferencesAgent.chat(projectId, message)
  ↓
1. 加载当前 WritingPreferences → 拼入 prompt
2. 调 LLM，prompt:
   "你是写作偏好调节助手。当前配置：
    对话密度：0.35
    爽点轮换：开启
    角色声音：开启
    ...
   用户说：「对话太少了，增加到40%」
   请判断用户意图，返回 JSON 更新配置。"
3. 解析 LLM 返回 JSON → 更新 WritingPreferences
4. 返回确认消息给作者
```

### Prompt 模板 `preferences-chat.st`

```
你是小说写作偏好调节助手。作者可以调整以下参数：

1. dialogueDensity（对话密度）：0-1 之间的小数，0.35 表示整章35%为对话
2. enableClimaxRotation（爽点轮换）：true/false
3. enableCharacterVoice（角色声音）：true/false，开启后每个角色有独立说话风格
4. enableKnowledgeQuotes（引用素材）：true/false，开启后角色可引用经典/诗词/兵法
5. preferredQuoteSources（引用来源）：数组，如["兵法","古籍","诗词"]
6. preventTransitionOverlap（过渡去重）：true/false

当前配置：
{{currentConfig}}

用户消息：「{{userMessage}}」

请解析用户意图，只修改用户明确提到的参数。
返回 JSON：
{
  "updates": {"dialogueDensity": 0.4},
  "reply": "已更新，下章开始对话占比目标设为 40%"
}
```

### 支持的交互场景

| 作者输入 | Agent 响应 |
|---------|-----------|
| "对话太少了" | dialogueDensity: 0.30 → 0.40 |
| "让夜北辰多引经据典" | characterVoiceProfile 更新 + 引用素材开启 |
| "不要每章都用智斗反转" | enableClimaxRotation: true |
| "配角说话太文绉绉了" | characterVoiceProfile 更新 |
| "增加一些诗词引用" | preferredQuoteSources += ["诗词"] |
| "当前对话占比多少？" | 回复当前值，不修改 |
| "恢复默认" | 重置为默认值 |

## 四、对话丰富化注入（ContextAssembler 改造）

### buildDialogueConstraints() 新增

注入到 `writingConstraints`：
```
□ 本章对话占比不低于 35%（以引号"标注的对话内容计算）
□ 每个出场角色至少说 2 句话，且符合其说话风格
□ 禁止连续 3 段纯叙述无对话
```
数值从 `WritingPreferences.dialogueDensity` 读取，作者可调。

### buildCharacterVoiceSection() 新增

注入到 `toSystemPrompt()` 的【出场人物】块中：
```
■ 夜北辰（主角）
  说话风格：引经据典，善用兵法典故，语气沉稳
  知识领域：兵法、古籍、阵法
```

### buildKnowledgeQuoteSection() 新增

注入到 `toUserPrompt()`：
```
【可用引用素材】
角色「夜北辰」精通【古籍】【兵法】，可引用：
■ 星陨抄本：北辰之星，当堕于尘，然后升于九天（古籍典故）
■ 星骸兵法：以弱击强，必先示之以弱，藏锋于钝（兵法谋略）
```
从 `KnowledgeEntry` 中匹配角色 `knowledgeDomains` 关键词。

### chapter-writing.st 新增 2 条件块

```
{{#if characterVoices}}
【角色说话风格要求】
{{characterVoices}}
{{/if}}

{{#if knowledgeQuotes}}
【可用引用素材（角色可自然引用以下内容展现学识）】
{{knowledgeQuotes}}
{{/if}}
```

在「写作铁律」中新增一条：
```
6. 本章对话占比不得低于 {{dialogueDensity}}%，对话必须推动情节或展现角色性格
```
