# Agent Harness + 上下文管理 全面改进方案

## 问题根因总结

### Harness 层（Agent 编排）
1. **无输出校验+重试**：WorldBuilder 返回 0 条目、Plotter 解析出 0 卷都静默落库
2. **ContinuityChecker 无反馈闭环**：HIGH 级矛盾只入 DB，不触发重写/修正
3. **StyleGuardian.checkConsistency 完全未接线**：风格漂移检测写了但从不上场
4. **写作循环无异常容错**：一章 LLM 失败崩溃整个 loop
5. **无 LLM 传输层重试**：429/瞬时网络错误直接致命

### 上下文管理层（召回与注入）
6. **无 token 预算**：世界观全量注入 + 伏笔全量注入，长篇撑爆 context window
7. **章节正文只索引前 1500 字**：中后段情节完全不被向量覆盖
8. **人物卡索引残缺**：只索引 name/role/personality/ability，丢弃 4 个字段
9. **无 score 阈值**：不相关的噪声结果也被注入 prompt
10. **无递归摘要**：写到第 50 章时，第 1-35 章的剧情完全不可见
11. **世界观双重注入**：全量 + 检索重复注入相同条目

## 实施计划（8 个 Task）

### Task 1：AgentHarness — 输出校验 + LLM 重试基础设施
**新建 `AgentHarness.java`**：通用的 Agent 执行器，封装"调用→校验→重试"
- `executeWithRetry(maxAttempts, supplier, validator)`：带校验的重试执行
- 校验器：WorldBuilder 校验"条目≥3"、Plotter 校验"卷≥1且章节≥1"、ChapterWriter 校验"内容≥500字"
- LLM 传输层在 `OpenAiCompatibleClient` 加 429/5xx 重试（3 次，指数退避）

### Task 2：Agent 输出校验接入
改造 WorldBuilder / Plotter / ChapterWriter 的输出路径：
- WorldBuilder：0 条目时重试（最多 2 次），仍失败则用 fallback（至少生成 1 条基础条目）
- Plotter：0 卷时重试；解析成功后校验章节数≥3
- ChapterWriter：内容为空或 <500 字时重试

### Task 3：ContinuityChecker 纠偏闭环
改造 `NovelOrchestrator.runWritingOneChapter`：
- 写完后调 ContinuityChecker（已有）
- **新增**：发现 HIGH 级人物/世界观矛盾时，触发 1 次重写（把矛盾描述加入 prompt 要求修正）
- 重写仍失败则保留原版本 + 标记 issue
- 接入 StyleGuardian.checkConsistency：每 5 章检测一次风格漂移

### Task 4：写作循环异常容错
改造 `runWritingLoop`：
- 每章 try-catch：单章失败不崩溃整个 loop，跳过该章并记录
- 连续 3 章失败才中止循环
- 新增"质量熔断"：连续 3 章 ContinuityChecker 都报 HIGH 严重度时暂停

### Task 5：召回质量修复
- `KnowledgeBaseService.saveCharacter`：补全 8 字段索引（加 motivation/relationships/growthArc/appearance）
- `EmbeddedVectorStore.search`：增加 score 阈值过滤（cosine < 0.2 丢弃）
- `ChapterWriterAgent`：章节正文按段落分块索引（每 ~800 字一块，id=`chapterId#N`），替换前 1500 字前缀
- 消除世界观双重注入：`ContextAssembler` 世界观条目≥10 时改为纯检索，<10 时全量+跳过检索段

### Task 6：Token 预算控制器
新建 `TokenBudget.java`：
- `estimateTokens(text)`：粗略估算（中文≈1.5字/token）
- `ContextAssembler.assemble` 增加总预算（如 12K token）
- 超预算时按优先级裁剪：任务>主角>近期摘要>上章原文>检索人物>检索设定>世界观>伏笔
- 每个 section 标注优先级和预估 token

### Task 7：递归摘要 + 卷级全局摘要
- 新建 `VolumeSummaryService`：每卷结束时生成卷级摘要（汇总本卷所有 3 章摘要）
- `ContextAssembler`：注入策略改为"近期 3 章摘要 + 当前卷摘要 + 前面卷摘要"
- 摘要触发从"每 3 章"改为可配置（默认 3）

### Task 8：验证 — 新建项目 5 章 + 质量评价对比
新建项目，写 5 章，跑质量评价，对比优化前后 5 个维度评分。

## 设计原则
- **渐进增强**：每个 Task 独立可验证，不破坏现有功能
- **可配置**：新增参数（token 预算、重试次数、摘要窗口）通过 yml 可调
- **兜底优先**：所有新增机制都有 fallback，不引入新的致命失败模式
