# 质量优化方案：精准修复 3 个系统 Bug

## 问题与根因总结

| # | 问题 | 根因 | 修复点 |
|---|------|------|--------|
| Bug 1 | 主角名漂移（祁渊→林风） | 人物卡只通过向量检索注入，检索失败时 system prompt 完全没有人物信息，LLM 自由发挥 | ContextAssembler: 强制注入主角+回退机制 |
| Bug 2 | 人设脱节（设定务实嘴炮，正文苦大仇深） | toSystemPrompt 只渲染了 4/8 个人物字段（name/role/personality/ability），漏掉 motivation/relationships/growthArc | WritingContext: 补全人物卡渲染 |

## 修复方案（3 个 Task）

### Task 1：ContextAssembler — 强制注入主角 + 回退机制

**文件：** `src/main/java/com/writing/novel/memory/ContextAssembler.java`

修改 `assembleRetrievedContext` 方法：

1. **主角强制注入**：检索完成后，检查 `relevantChars` 是否包含 role 含"主角"的人物。如果不包含，从 `allChars` 中强制补充所有主角。主角不依赖检索命中。

2. **空结果回退**：如果向量检索完全失败（`searchResults` 为空或异常），回退为注入全部人物（`allChars`），并加 try-catch 防止 embedding API 失败中断写作。

3. **人物数量上限**：为避免人物过多撑爆 prompt，回退时最多注入 8 个人物（主角优先）。

```java
private void assembleRetrievedContext(String projectId, String queryText, WritingContext ctx) {
    List<Character> allChars = knowledgeBase.findAllCharacters(projectId);
    if (allChars.isEmpty()) return;

    // 向量检索相关人物（try-catch 防止 API 失败中断写作）
    List<String> relevantIds = List.of();
    try {
        var searchResults = vectorRetrieval.search(queryText, projectId, RETRIEVAL_TOP_K);
        relevantIds = searchResults.stream().map(r -> r.id()).toList();
    } catch (Exception e) {
        // 检索失败，回退为注入全部人物
    }

    List<Character> relevantChars = allChars.stream()
            .filter(c -> relevantIds.contains(c.getId()))
            .collect(Collectors.toList());

    // 强制注入主角（主角不依赖检索命中）
    for (Character c : allChars) {
        if (isMainCharacter(c) && !relevantChars.contains(c)) {
            relevantChars.add(0, c);  // 主角放第一位
        }
    }

    // 回退：如果检索完全没命中，注入全部人物（最多8个，主角优先）
    if (relevantChars.isEmpty()) {
        relevantChars = allChars.stream().limit(8).collect(Collectors.toList());
    }

    ctx.setRelevantCharacters(relevantChars);
    // ... relevantSettings 逻辑不变
}

private boolean isMainCharacter(Character c) {
    String role = c.getRole();
    return role != null && (role.contains("主角") || role.contains("男主") || role.contains("女主"));
}
```

### Task 2：WritingContext — 补全人物卡字段渲染

**文件：** `src/main/java/com/writing/novel/memory/WritingContext.java`

修改 `toSystemPrompt()` 中【出场人物】段，渲染全部 8 个字段，并强化锚定语气：

```java
if (!relevantCharacters.isEmpty()) {
    sb.append("【出场人物（必须严格遵守以下设定，不得改名或改变性格）】\n");
    for (Character c : relevantCharacters) {
        sb.append("■ ").append(c.getName()).append("（").append(c.getRole()).append("）\n");
        if (c.getPersonality() != null) sb.append("  性格：").append(c.getPersonality()).append("\n");
        if (c.getAbility() != null) sb.append("  能力：").append(c.getAbility()).append("\n");
        if (c.getMotivation() != null) sb.append("  动机：").append(c.getMotivation()).append("\n");
        if (c.getAppearance() != null) sb.append("  外貌：").append(c.getAppearance()).append("\n");
        if (c.getRelationships() != null) sb.append("  人物关系：").append(c.getRelationships()).append("\n");
        if (c.getGrowthArc() != null) sb.append("  成长弧：").append(c.getGrowthArc()).append("\n");
    }
    sb.append("\n");
}
```

关键变化：
- 标题加"必须严格遵守以下设定，不得改名或改变性格"——强化 LLM 锚定
- 每个人物用 ■ 分隔，字段换行展示（原来是一行挤在一起，LLM 容易忽略）
- 补全 motivation/appearance/relationships/growthArc 4 个字段

### Task 3：NovelOrchestrator — 写作循环加入连续性检查

**文件：** `src/main/java/com/writing/novel/orchestrator/NovelOrchestrator.java`

修改 `runWritingOneChapter`，写完章节后调用 ContinuityChecker，发现 HIGH 级别人物矛盾时记录到日志：

```java
public Chapter runWritingOneChapter(String projectId) {
    // ... 原有写作逻辑不变 ...
    Chapter chapter = chapterWriter.write(...);
    p.setCurrentChapterIndex(chapterIndex);
    repository.saveProject(p);

    // 写完后做连续性检查（新增）
    checkContinuityAfterWriting(projectId, chapterIndex, chapter);

    if (chapterIndex % 3 == 0) {
        generateSummary(projectId, chapterIndex - 2, chapterIndex);
    }
    return chapter;
}

private void checkContinuityAfterWriting(String projectId, int chapterIndex, Chapter chapter) {
    try {
        // 收集相关设定供 checker 参考
        String settings = collectSettingsForCheck(projectId);
        var issues = continuityChecker.check(projectId, chapterIndex,
                chapter.getContent(), settings);
        // HIGH 级别人物矛盾记录警告（不中断写作，但留下问题记录供质量评价使用）
        long highSeverity = issues.stream()
                .filter(i -> i.getSeverity() == ContinuityIssue.Severity.HIGH)
                .count();
        if (highSeverity > 0) {
            // issues 已由 ContinuityCheckerAgent 保存到 repository
            // 这里只做日志记录
        }
    } catch (Exception e) {
        // 检查失败不中断写作
    }
}
```

关键设计决策：
- **检查不中断写作**：即使发现矛盾也继续写（否则连续写作会频繁中断）。但 issue 会保存到数据库，质量评价 Tab 能看到。
- **try-catch 兜底**：LLM 检查调用可能失败，不能让整个写作循环崩掉。
- 这是 spec 第 6 节 WRITING 子状态机的简化实现（完整实现会在交互模式下暂停纠偏，但 Solo 模式下记录问题更实用）。
