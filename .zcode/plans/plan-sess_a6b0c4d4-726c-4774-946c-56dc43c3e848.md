# Phase 8: 创意多样性 + 叙事连贯性 + 读者驱动 Agentic Loop

## 设计理念

**三层质量保障**，全部通用化、零硬编码：

```
Layer 1: 创意多样性（生成时预防）
  ├── 历史感知 Prompt（让 Agent 看到之前做过什么）
  ├── 通用创意指令（替换硬编码黑名单）
  └── 多维度重复检测（开场/冲突/爽点轮换）

Layer 2: 叙事连贯性（生成时预防）
  ├── 叙事线索追踪（活跃/悬挂/已回收）
  ├── 悬挂线索检测（超过N章未跟进→警告）
  └── 跨章衔接约束（平行线索必须回收）

Layer 3: 读者驱动 Agentic Loop（生成后检验+自动修复）
  ├── 每章写完 → 读者 Agent 检验 → 低分自动重写
  ├── 卷末 → 全卷综合检验 → 改进建议注入下卷
  └── 全书完成 → 全书终审 → 修改建议 + 自动修复
```

## p8-1: 历史感知 Prompt + 通用创意指令

### 问题
每次生成相同题材（查账/鬼市/县丞），因为 Agent 看不到之前做过什么，且黑名单硬编码玄幻套路。

### 方案

**CreativeDiversityService**：
1. 每个 Agent 生成后记录关键元素摘要（存 `generation_logs` 表）
2. 下次生成时注入 `diversityGuide`：「以下是近期生成中使用过的方向，请探索不同角度」
3. **不硬编码任何套路**——只是让 LLM 知道"你之前做过 X"

**Prompt 重写**：
- 删除 `plotting.st` 和 `chapter-writing.st` 中的硬编码 ❌ 黑名单
- 替换为通用创意指令：「如果你觉得某个桥段很常见，就不要用它」
- `worldbuilding.st` 维度选择灵活化

### 修改

## p8-2: NarrativeThreadTracker — 叙事线索追踪

### 问题
相邻章节可切换线索（允许），但后续必须衔接回来。当前无追踪机制，导致叙事遗漏和线索断裂。

### 方案

**NarrativeThread 模型**：
```java
class NarrativeThread {
    String name;           // "主角查账线"
    ThreadStatus status;   // ACTIVE / SUSPENDED / RESOLVED
    int firstSeenChapter;
    int lastSeenChapter;
    int suspenseChapters;  // 悬挂了多少章
}
```

**追踪逻辑**：
1. 每章写后由 LLM 提取本章涉及的叙事线索
2. 未在本章出现的 ACTIVE 线索 → `suspenseChapters++`
3. `suspenseChapters > 阈值`（默认5）→ `ContinuityIssue(PLOT, MEDIUM)`
4. 线索在后续章节再次出现 → `suspenseChapters` 清零

**注入到写作上下文**：
```
【叙事线索追踪（请确保不遗漏以下线索）】
■ 活跃：主角查账线（第1-3章）— 需持续推进
■ 悬挂（3章）：北境军镇（第2章提及）— 近期需回收
■ 悬挂（5章）：废太子传闻（第1章）— 需尽快回收
```

## p8-3: ReaderReviewAgent — 读者驱动 Agentic Loop

### 问题
当前质量评价只在卷末触发（QualityEvaluationAgent），太晚。需要每章都有"读者"视角的即时检验，低分自动修复。

### 方案

**三层检验循环**：

**A. 每章即时检验（Chapter Review Loop）**

每章写完后，`ReaderReviewAgent` 以大众读者视角检验：
- 这章吸引人吗？开场是否抓人？
- 有没有看不懂的跳跃？需要补充过渡？
- 角色行为是否合理？对话是否自然？
- 章末是否让你想看下一章？

评分 1-10，<7 分则自动重写（带改进建议），最多重写 1 次。

```
写章 → ReaderReviewAgent.review() → score >= 7 → 通过
                                → score < 7 → rewriteForCorrection(改进建议) → 再检验
```

**B. 卷末综合检验（Volume Review）**

每卷结束时，以全书读者视角检验：
- 整卷剧情是否连贯？
- 人物弧线是否清晰？
- 有没有未回收的悬念让人困惑？
- 节奏是否合理？

低分维度的改进建议注入下一卷的 `qualityFeedbackSection`。

**C. 全书终审（Final Review）**

全书完成后，`FinalReviewAgent` 终审：
- 全书主线是否完整？
- 所有重要线索是否回收？
- 角色成长弧是否令人满意？
- 开头和结尾是否呼应？

生成终审报告 + 可选自动修复建议。

| 文件 | 改动 |

| `agent/ReaderReviewAgent.java` | **新建**。读者视角章节检验 |
| `prompts/reader-review.st` | **新建**。读者视角 prompt |
| `agent/FinalReviewAgent.java` | **新建**。全书终审 |
| `prompts/final-review.st` | **新建** |

## 完整 Agentic Loop 流程

```
写第N章正文
  ↓
ReaderReviewAgent.review(chapter N)  ← 读者视角即时检验
  ↓ score >= 7
通过 → 实体提取 → 伏笔提取 → 叙事线索更新 → 多样性追踪
  ↓ score < 7
自动重写（带改进建议）→ 再检验 → 通过或保留
  ↓
NarrativeThreadTracker 更新线索
  ↓
悬挂线索 > 5章 → ContinuityIssue 警告 → 下章注入回收约束
  ↓
卷末 → Volume Review（全卷连贯性）→ 改进建议注入下卷
  ↓
全书完成 → Final Review（全书终审）→ 修改建议
  ↓
可选：自动修复（rewrite-chapter）
```
