# Spec: 审阅入口与阅读工作区修复

## 背景与动机

用户在 main@7f666b0 人工复核“凤鸣九州”失败：审阅内容无可见响应、审查意见文字拥挤、正文过窄。真实浏览器1440px复现第63章：点击前后均无审查对话框；正文卡547px、审查卡244px。正文中的每段操作又占约200px，标题被同排操作挤掉；评分五列被压缩。修复前截图 /tmp/fengming-before-desktop.png。

## 目标

1. 审阅内容每次点击都打开当前章节的完整审查面板；待审直达原子切换章节及页签，不受旧页签闭包影响。
2. 章节目录+正文两列；审查详情按需抽屉打开，桌面/窄屏使用同一内容。正文标题与操作分行，段落操作不挤占文本行宽。
3. 专注阅读收起项目侧栏及章节目录，可明确退出；正文随页面滚动，不陷入70vh嵌套滚动区。评分、标签、长意见换行，窄屏无页面水平溢出。

## 非目标

不调整模型、审批规则、数据库与文学标准；不触发真实项目创作或自动批准。保持已有编辑/版本/候选流程。

## 验收标准

- [x] 先运行新增Playwright测试，证实原版点击不打开面板及正文宽度失败。
- [x] 同页签打开/关闭/再次打开审查，其他页签待审直达正确章节，空章节给出明确提示。
- [x] 1280px正文文本宽度至少550px，专注后至少850px；390px无页面水平溢出；长意见、评分标签不重叠。
- [ ] mvn compile && mvn test；前端构建；完整协作浏览器回归通过，合并后干净检出复验。
- [ ] 用凤鸣九州只读复核实际页面，重新打包启动供用户验收。

## 影响面

- 涉及模块：ProjectWorkspace、InteractiveReview、Playwright。
- prompt、schema、质量基线：无变化。

## 风险与备选方案

仅增大三栏比例仍会挤压小屏；独立审阅页会丢失当前编辑上下文。采用现有工作区+统一抽屉，并保留表单内容及原批准守卫。所有修改通过本轮浏览器回归验证，不改变已存小说。
