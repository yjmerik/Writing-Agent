### NCS-075 worker 收尾窗口批准提示与排队（commit `647daa9`）

- 先失败测试 `WritingTaskExecutorBeginWorkConflictTest`（4 用例：编译期 RED → GREEN）：
  RUNNING 任务占坑 → `WORKER_FINALIZING`（文案含"收尾/稍候"）；匿名同步占坑 →
  `SYNC_WORK_BUSY`；非运行任务占坑 → 无细分码、保持"暂停或取消"指引。
  三个既有工权测试（ChapterDirectEdit / RestoreOwnershipMessage /
  ManualReviewResolution）的断言随细分语义更新为 `SYNC_WORK_BUSY`（匿名占坑场景）。
- 前端：批准对 409 按 code 分支——REVIEW_CONFLICT 保持"重读+人工确认"；
  WORKER_FINALIZING 以同一幂等键自动重试（≤3 次、间隔 15s）；其余如实展示服务端原因。
- 真实 UI：补查占坑期间点「确认已复核并批准」→ toast
  「批准未生效：同步内容处理进行中，请等待其完成或取消该操作」——不再误报"请确认新稿"。

### NCS-074 同步占坑可观测可取消（commit `eba271c`）

- 先失败测试：`WritingTaskExecutorSyncWorkTest` 6 用例（登记/kind 前缀/取消释放/
  任务型不误伤/非持有者 endWork 不清登记/无占坑取消 false）+ `WorkspaceStatusApiTest`
  新增 2 用例（workspace 暴露 activeWork + 取消端点释放；任务型占坑不暴露也不可经该路径取消）。
- 实现：beginWork 登记内存态 SyncWorkInfo（kind=workId 去 UUID 前缀）；workspace 增
  `activeWork{kind,label,startedAt,elapsedSeconds}`；新端点 `POST /active-work/cancel`
  仅对匿名占坑释放工作权。诚实边界：取消不中断进行中的调用，原操作若完成仍按稿件身份落库。
- 真实 UI：补查启动后——按钮旁「补查进行中（已 6 秒）」+「取消等待」；
  协作栏标签「连续性补查中 · 已 4 秒」+「取消该操作」+ 说明文案；
  点「取消等待」→ toast「已取消等待并释放项目工作权…」→ 协作栏恢复非占坑态。
