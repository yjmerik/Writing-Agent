# Harness 创建计划

基于 harness-creator 的 5 个子系统，为 WritingAgent 项目创建定制化 harness：

## 创建文件清单

### 1. `AGENTS.md` — 启动路径 + 工作规则
定制内容：
- 项目概述：长篇小说自动写作 Agent 系统（7 Agent + 3层记忆 + 状态机编排）
- 启动流程：`pwd` → 读 AGENTS.md → `./init.sh` → 读 feature_list.json → `git log --oneline -5`
- 工作规则：一次一个 feature、必须跑验证、更新 artifacts、不越界改文件
- 验证命令：`mvn compile` + `mvn test`
- 定义完成：实现+测试通过+证据记录+可重启

### 2. `feature_list.json` — 特性状态追踪
基于 4-Phase 优化方案，创建 16 个 feature 条目：
- Phase 1（信息流）：premise注入、CharacterDesigner注入世界观、Plotter注入世界观+人物、卷摘要全量注入、chunk检索修复、styleGuide动态注入
- Phase 2（规模）：大纲参数化、世界观选样优化、worldbuilding.st去法则化
- Phase 3（闭环）：Issue.resolve接通、StyleGuardian闭环、伏笔系统、卷末质量评价
- Phase 4（UI+鲁棒）：Steps状态修复、按钮互斥、catch日志

### 3. `progress.md` — 会话连续性日志
当前状态快照：86测试通过、48个commit、5轮优化完成、DeepSeek评分8/10、30个架构问题待修

### 4. `init.sh` — 标准启动验证脚本
```bash
#!/usr/bin/env bash
set -e
echo "=== WritingAgent Verification ==="
mvn compile -q
echo "✅ Compile OK"
mvn test
echo "✅ All tests passed"
```

### 5. `session-handoff.md` — 跨会话交接
记录当前优化方案的 4 个 Phase、下一步行动计划、已知风险

## 设计原则
- 所有文件内容**针对 WritingAgent 项目定制**，不用通用占位符
- feature_list.json 的 16 个条目直接对应架构审查的 30 个问题（合并相关项）
- 验证命令用 `mvn compile` + `mvn test`（Java Maven 检测）
