02状态机编排

NovelOrchestrator 驱动项目生命周期，各步骤具备幂等检查（DB 已有产物则跳过）。单章失败退避重试不跳章，<500 字的空内容不入库。

CONCEIVING世界观 / 人物 / 大纲
→
PLANNING细化大纲
→
WRITING逐章创作循环
→
VOLUME_DONE单卷完结
→
FINAL全书完结

核心入口方法

  • runConceiving(projectId) — 构思阶段：WorldBuilder → CharacterDesigner → Plotter，信息逐级注入（世界观 → 人物 → 大纲）
  • step(projectId) — 按当前状态推进一步
  • runWritingOneChapter(projectId) — 单章流水线：上下文组装 → 写作 → 一致性/风格检查 → 记忆更新
  • runWritingLoop(projectId, maxChapters) — 批量写作循环（容错重试）
  • rewriteChapter(...) / auditForeshadowingImportance(...) — 重写与伏笔审计

03三层记忆系统

ContextAssembler 将三层记忆按 TokenBudget 预算汇成 WritingContext。【故事原旨】（Outline.premise + Project.concept）置于最前且永不被裁剪。

① 结构化知识库

KnowledgeBaseService · 世界观条目、人物卡、伏笔、实体图谱（Entity / EntityEdge）、叙事线索，存于 SQLite。

② 滚动摘要

SummaryService · 章级摘要 + 卷级摘要。卷级摘要（覆盖 >3 章）全量注入，细粒度摘要按 window=5 滚动。

③ 向量检索

VectorRetrievalService · 章节正文分 chunk 嵌入（EmbeddedVectorStore），写作前语义召回相关前文。

05Prompt 模板体系（20 个 .st）

Agent 的 systemPrompt 一律通过 promptService.render(templateName, vars) 渲染，支持变量插值与条件块，禁止硬编码。模板变量名必须与 Agent 代码的 Map.of(...) 保持一致。

08单章写作流水线（WRITING 阶段）

上下文组装ContextAssembler
→
章节写作ChapterWriter
→
一致性检查ContinuityChecker / ConsistencyGate
→
风格守护StyleGuardian
→
记忆更新摘要 / 实体抽取 / 伏笔 / 向量索引
  • 入库门槛：正文 ≥ 500 字，空内容不落库
  • 失败策略：退避重试，不跳章
  • 写后异步链：EntityExtractor（实体图谱）→ ForeshadowingExtractor（伏笔登记）→ NarrativeThreadExtractor（叙事线索）→ SummaryService（滚动摘要）→ 向量索引
  • 多样性控制：ClicheDetector、DiversityTracker、ClimaxDiversityTracker 防止套路化

09关键架构约束

  • Agent 间不直接调用 — 全部经 NovelOrchestrator 调度
  • Prompt 外置 — systemPrompt 必须经 promptService.render(...)，禁止硬编码
  • SPI 分层 — 业务层只依赖 NovelRepository / VectorStore / EmbeddingProvider 接口
  • 幂等性 — runConceiving 各步骤先查 DB，已有产物则跳过
  • 写作循环容错 — 单章失败不跳章（退避重试），空内容不入库（≥500 字门槛）
  • SQLite 单进程 — 避免多个 write-all 并发操作同一项目
