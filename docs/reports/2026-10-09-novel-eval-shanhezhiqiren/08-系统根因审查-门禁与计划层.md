# 系统根因审查 ③：质量门禁与计划/编排层（子 Agent 独立审查，全部 file:line 已核实）

覆盖条目：A2 零回报 / A5 无阶段感 / D2 反派弱 / D4 伏笔悬置 / D1 弧光 / E1 术语无解释

## 逐缺陷根因

**A2 零回报兑付（55章无爽点）｜高置信**：**读者评审是单章盲评**——ReaderReviewAgent.java:34-40 输入仅本章正文，reader-review.st 渲染时 Map.of() 零变量注入（:35），维度全为章内指标；它看不见「连续91章同型钩子」「待验860次」「无回报」。唯一全书视角的卷末 QualityEvaluationAgent（:68-74）输入被截断（摘要800字/正文采样9000字），产出仅以「改进方向」文本注入后续写作（ContextAssembler.java:1271-1291），**不回改大纲、不阻断推进**。grep 全库无 payoff/回报预算组件——A2 是**组件缺失**非阈值失准。

**A5 无分卷阶段感｜高置信**：VOLUME_TREND_WARNING **只发事件无执行回路**（NovelOrchestrator.java:1646-1652 仅 EventLog.emit）；自动重规划仅每5卷（:1572 volumeIndex%5==0），「重规划未写卷」是手动按钮（ContentController.java:297-301）；卷边界不停车（:2090-2093 直接翻回 WRITING）。**最致命**：延迟生成下一卷时 tryExtendLayeredOutline 传给 planVolume 的 volumeSummary 是占位字符串「（延迟生成，根据总纲规划）」（:2927-2935）——趋势警告/评价记录/伏笔台账/阶段目标**均不传入**；volume-outline.st 变量表无任何阶段/弧线/待回收伏笔变量。→ 每卷规划输入同质化 → ch9 后无阶段差异。

**D4 伏笔悬置130条无回收｜高置信**：告警链路完整（ChapterProduction.java:190-206→SuspenseReminderPolicy 写 MEDIUM issue）但断三处：①提醒仅覆盖 mustResolve||HIGH（SuspenseReminderPolicy.java:27），130条中大量 LOW/MEDIUM 零提醒；②**僵尸惩罚负反馈**——伏笔按打分选top-12注入（ContextAssembler.java:825-837），cast未命中且悬置>25章 -50（:807），**越悬置越被挤出注入集→永无回收**；③注入是参考性文本而章节实际任务由 synopsis 决定——写手服从大纲，大纲不排回收，回收永不发生。DetectorTrendService.TREND_TYPES 不含 FORESHADOWING。

**D1 主角弧光无挫败｜高置信**：**ArcScheduler.java:48 显式排除主角**（if role.contains("主角") continue）——主角不在弧光调度内；ArcUpdater.java:76-104 每10章从近章摘录重新描述 growthArc——纯描述无「本卷应达阶段 vs 实际」对照；chapter-writing.st 铁律7是章内局部困境非全书挫败预算。

**E1 术语无解释｜高置信**：chapter-writing.st:8 铁律3只有「严格遵守世界观设定」（遵循方向），无「新制度术语首次出现须借角色对白/事件向读者解释」规则；GenreRuleProvider.java:50-58（HISTORICAL）与 historical.json 均无解释性要求；铁律7「诏书用大意是概括」反而抑制展开。

## 架构性结论：缺失的一层
系统完备的是**章内管线**（写→查→评→重写）；缺失的是**全书计划控制层**——大纲一旦生成即被视为既定事实顺写，卷末所有全书级信号（趋势警告/评价/伏笔台账/弧线）都汇入「建议文本」而非「计划修订」，且**永不回流到下一卷 planVolume 的输入**。这是「单章7分、全书4.2分」断层的结构性解释。

## 最高杠杆修复（缺失组件形态设计）
1. **VolumeController（卷间计划修订器）**：卷末停车点汇聚 趋势告警+评价低分维度+到期伏笔清单+弧线应达阶段，组装为结构化约束（「本卷必须兑现伏笔X」「主角须遭1次实质挫败」「反派须落1次重击」）传入 planVolume 替换占位串；%5 降为每卷
2. **PayoffLedger（回报预算器）**：按卷登记爽点/伏笔承诺/威胁事件的计划兑付章，逐章后处理核销，未兑付升级 PLOT HIGH 进重写仲裁；僵尸伏笔从 -50 改为逾期加权强制注入
3. **BookEditorAgent（全书读者评审）**：卷末以「近1卷正文+累计钩子类型统计+主线节点表」评全书体验分（对齐4.2维度），低于阈值自动触发修复1；reader-review.st 注入前N章钩子摘要弥合单章/全书断层
