# 写作循环稳定性修复方案

## 问题根因（按严重程度）

| # | 问题 | 根因 | 影响 |
|---|------|------|------|
| P0 | **空章节入库（0字）** | ChapterWriter.write 重试后仍空时无条件保存 + 索引无条件推进 | 脏数据，章节断裂 |
| P0 | **失败时跳章** | runWritingLoop catch 块 `currentChapterIndex+1` | 剧情永久断裂 |
| P1 | **重复章节** | rewrite 生成新 UUID Chapter，旧的不删，DB 无 (project_id, chapter_index) 唯一约束 | 数据不一致 |
| P1 | **contentFilter 无策略** | HTTP 400 内容审查直接抛异常，无温和 prompt 重试 | 可恢复错误变致命 |
| P2 | **空内容重试用相同 prompt** | 重试时 `req` 不变，LLM 大概率返回相同空结果 | 重试无效 |

## 修复方案（5 个 Fix）

### Fix 1：空章节不入库 + 失败不跳章（P0）
**NovelOrchestrator.runWritingOneChapter + runWritingLoop**
- write 返回后检查 `wordCount >= 500`，不达标则不保存、不推进索引、抛异常
- runWritingLoop catch 块：**不推进索引**，退避后重试同一章；单章重试 3 次仍失败才跳过（且标记跳过）
- runWritingOneChapter 开头加幂等检查：该章已存在且 wordCount≥500 则跳过

### Fix 2：章节去重——rewrite 原地更新（P1）
**ChapterWriterAgent.rewrite + NovelOrchestrator.rewriteWithCorrection**
- rewrite 改为返回 `String content`（而非 new Chapter），由调用方写回原 chapter
- rewriteWithCorrection 把新 content 写回原 chapter 的 id，触发 ON CONFLICT(id) DO UPDATE

### Fix 3：contentFilter 温和重试（P1）
**OpenAiCompatibleClient + ChapterWriterAgent**
- OpenAiCompatibleClient 识别 contentFilter（HTTP 400 + code 1301/content_filter），抛专用 `ContentFilterException`
- ChapterWriterAgent 捕获后：第一次用温和 prompt（"避开暴力直白描写，改用侧面烘托"）+ 降温度重试；第二次再降温度 + 缩短 maxTokens

### Fix 4：空内容重试改用变化 prompt（P2）
**ChapterWriterAgent.write**
- 当前重试用相同 req → 改为第二次拼接引导语："上一次输出为空或过短，请严格按四段式结构完整输出不少于2500字正文"

### Fix 5：OkHttp callTimeout + retryOnConnectionFailure
**OpenAiCompatibleClient**
- 加 `.callTimeout(Duration.ofMinutes(3))` 防止单请求挂死
- 加 `.retryOnConnectionFailure(true)` 自动重试网络抖动

## 验证
新建项目写 5 章，人为触发空内容/审查场景，确认不跳章、不产生空章节、重复章节消除。
