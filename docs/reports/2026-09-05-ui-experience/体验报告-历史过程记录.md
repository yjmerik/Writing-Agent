## 优先问题与复验标准

1. **P1：作者小改不能可靠保留。** 输入框已核对提交内容，主页面一度显示改稿，刷新却成为另一版本。建议作者保存独立完成，后续AI修改必须给候选并明确确认。复验应逐字比较提交、处理结束、刷新及下一次继续后的内容；冲突保留作者草稿。这里只报告可观察的覆盖，不推断内部原因。
2. **P1：最新总纲及章节计划没有约束正文。** 最新第1章为档案移交拒签，第2章为2005水文缺页，第3章为周泊听障/旧标尺；实际仍沿旧断缆、1992暗涵、匿名值班表发展。建议显示采用的计划版本，失效旧计划不能继续主导生成。复验需逐章核对人物、场景和推进事件，不能只核标题相同。
3. **P1：操作完成与工作权释放不一致。** 首章接手曾互锁；本次连续工具显示“第4章完成”后五分钟无细分检查进展；段落应用已能在另页读到新版本，原弹窗却持续加载。建议区分正文保存、质检、资料更新、全部完成，显示当前步骤和已耗时，并提供安全取消。复验要求停止后能编辑、批准、继续，明确哪些工作仍未结束。
4. **P1：审核证据与正文版本脱节。** 摘要、问题数量和问题引用与当前稿不一致。每条评审应绑定章节版本、引用位置和时间；修改后标记过期，批准前刷新证据。历史问题与当前问题分开。
5. **P2：整章预览反复无有效候选。** 两种要求均失败，只有通用错误。应保留要求和原稿，提示是否可缩小范围、人工编辑或安全重试；失败不可表现为修改完成。
6. **P2：全文评价跨标签丢失，资料引用不可靠。** 保存评审历史、对应版本和参与材料范围。已有卡片不可被误判为缺失，未读取与不存在应区分。复验切页、刷新、重新进项目仍能查看同一评审。
7. **P1：段落应用报失败，实际已经保存。** 从22:00左右确认应用到最终报错约8分钟；显示“应用失败：signal is aborted without reason”，真正刷新却得到v6/2769字。逐字比较只有所要求的8字符日期增加。建议明确已保存内容和失败的后续步骤，提供查询结果而非诱导重复应用。复验应覆盖长处理/超时，错误结果与真实保存状态一致。证据63—65。
8. **P2：段落预览暴露内部结构。** 作者需在id/projectId/passageIndex/version等JSON中找修改文字。应直接呈现文字差异，技术诊断信息折叠；第1段与passageIndex 0也不应混在作者流程中。

## 主要卡点与优化空间

### P1-01：启动检查通过，真实生成却被缺失凭据阻断

**复现：** 空项目创建 → 开始协作 → 等待构思。界面显示 `Embedding 调用失败: HTTP 401`，英文提示没有提供 API key。

**影响：** 用户已完成输入并等待了生成，才知道运行条件不满足。编译、单元测试和前端构建通过，并不能证明真实模型链路可用。本次阻断发生在独立启动实例，不据此断言所有环境都缺少凭据。

**建议：** 在“开始协作”前提供模型与向量服务的就绪检查；明确缺失哪项配置、由谁修复；配置问题解决前避免重复启动同样的失败任务。产品层可以提供检查结果，底层凭据不应暴露给作者。

**复验标准：** 缺少向量凭据时，生成开始前即显示可操作的错误；补齐后，同一项目可以保留产物并正常恢复，不必重建。

### P1-02：故障提示有技术异常，没有可完成的恢复路径

**观察：** 协作栏显示英文 HTTP/JSON 异常片段，主要操作仍是“继续协作”“审阅内容”；说明文案建议编辑内容后继续。页面没有区分配置失败与需要作者改稿，也没有说明一条世界观是否完整、重试将从哪里开始。

**影响：** 作者无法判断该重试、等待、改稿还是联系维护者，也不知道重复操作会否继续计费。

**建议：** 显示“向量服务未配置，创作暂停；已有 1 条设定已保存”。提供检查配置、重试当前步骤和查看保留内容的明确入口；展示失败时间、步骤和重试范围。

### P1-03：正常长度的构思把桌面项目表格撑到五千像素

**复现：** 创建本次 353 字构思项目 → 返回列表。在 1440 像素视口中，表格容器宽 1004 像素、内容宽 5035 像素；构思列宽 4606 像素。“进入”按钮横坐标约 5139，进度和标签也被挤出可见区域。

**影响：** 合法且被表单鼓励的详细构思，使核心导航和进度难以发现。实际需点击可见书名进入项目。

**建议：** 限制构思列宽，使用两三行摘要与展开阅读；固定主要操作列。按接近 500 字的合法输入测试，而非只用短标题和短构思。

**复验标准：** 1440 像素桌面与 375 像素手机下，500 字构思不挤走进入入口、状态和进度；展开后可读完整构思。

### P1-04：无法评价的空小说被显示为“评价完成，1/10”

**复现：** 0 章、0 字 → 质量评价 → 开始质量评价。页面先显示“正在阅读全文”，最终绿色成功提示“评价完成”，总分 1/10，世界观 5/10，其余维度 1/10。

**矛盾证据：** 同一份评语明确写着“无正文章节、人物卡、大纲、前情摘要和已确立事实……无法对小说质量做出有效评分”。

**影响：** 把材料不足误表述成作品质量差，污染评分和用户信任，还浪费一次评审等待。建议文案虽然写了“写完若干章节后评价”，却没有阻止空评价。

**建议：** 正文为空时禁用全文评价并解释前置条件；支持独立的设定检查。即使模型返回数字，只要材料不足，也应显示“暂不可评价”，不能绘制正式分数。

**复验标准：** 空正文不启动全文评价、不出现总分；材料不足、评审失败和评价完成是不同状态。

### P1-05：一次失败重试又生成同城的另一版设定

**复现：** 首轮失败后保留“白砂城”设定 → 作者将名称改为“白沙城”并保存 → 添加城市名铁律 → 点击“继续协作” → 再次 401。

**观察：** 原“白沙城”保留，新增另一条“白沙”。第一条描述支流与海潮交汇、三道闸口和白砂埭；第二条重新描述江湖河三水系、半月形老城区与水患棋盘。两条指向同一城市，但没有合并、版本关系或作者确认提示，人物和大纲仍为空。

**影响：** 重试没有完成当前步骤，却积累了同一设定的不同描述；会增加作者整理负担和后续上下文歧义。本次含一次作者改名，尚未验证完全不编辑时是否同样追加，不能直接据此定位后端幂等性根因。

**建议：** 界面明确展示步骤内已完成的产物，恢复时对已有设定进行匹配与去重；新的差异以修订候选呈现，保护作者确认的版本。

**复验标准：** 对相同的“失败—作者编辑—恢复”路径，恢复不产生同实体平行设定，且作者内容不被覆盖。

### P2-01：项目列表隐藏了失败状态，10% 的含义不清楚

**观察：** 工作台显示“创作遇到问题”，返回列表却显示“构思中，0/200 章·10%”，未见失败标签。

**影响：** 用户可能误以为后台仍在推进；10% 紧贴章节数，容易被理解为作品完成比例。本报告不据此断言百分比计算错误，问题是界面没有解释它代表阶段进度还是正文进度。

**建议：** 分开展示“任务：失败待处理”“阶段：构思”“正文：0/200 章”，并给出失败摘要和恢复入口。

### P2-02：长任务等待信息不足

**观察：** 协作栏只有“搭建世界、人物与全书框架”和总章数，未展示当前子步骤、累计等待时间、最近一次产物或模型状态。创作工具中的“30–60 秒”说明指向单章，不足以帮助判断长篇构思的等待。

**建议：** 将世界观、人物、总纲、分卷规划分别标记为待处理/进行中/已完成；显示真实已耗时和最近活动。在缺乏历史数据时，不给虚假的精确剩余时间。

### P2-03：空状态把用户引向当前页不存在的按钮

**观察：** 默认章节页提示“暂无章节。点击‘写一章’开始创作”，当前页只有“新增章节”和“刷新”，主要生成入口实际位于上方“开始协作”。大纲空态又提示先运行“构思”并手动刷新。

**建议：** 空态直接提供与当前阶段相符的主操作，统一到协作入口；自动更新生成产物，保留刷新作为辅助。

### P2-04：明确专名在首个产物就发生偏移

**观察：** 构思指定“白沙”，生成条目却是“白砂城”，正文又加入“白砂埭”。本次已通过作者编辑把城市名改回“白沙城”。

**影响：** 这是本样本中已确认的构思遵循问题，不能单凭一次样本推断整个系统的长期一致性表现。

**建议：** 从构思提取城市、人物、时间和不可变约束，生成前让作者确认并锁定；生成后展示与原始构思的差异，避免作者逐条搜错字。

### P2-05：内容工具暴露内部术语

**观察：** 作者保存后，真典页直接显示 `WORLD_RULE`、`【HUMAN_PATCH】` 和“人补丁”。

**建议：** 用“世界规则”“作者确认”“作者补充”作为可见标签，内部标记不混入可编辑正文。

### P2-06：项目规模与审核选项不够一致

**观察：** 创建页只有 24/100/200/400 章，没有自定义字数；初始审核节奏只有主动接手和每章审阅，进入工作台后才出现卷末审阅。

**建议：** 支持目标字数与章数换算、自定义规模和预估资源用量；在新建页就提供适合长篇的卷末审核，解释各选项适用场景。

### P2-07：手机宽度下铁律和伏笔输入框溢出

**观察：** 模拟 375 像素视口，页面 `clientWidth=375`、`scrollWidth=392`；“新增铁律”和“种下伏笔”输入框从 x=32 延伸到 x=392。此项依据页面几何数据确认，未对手机视觉样式作完整验收。

**建议：** 这两组表单使用容器宽度约束，并让按钮在窄屏下换行；以实际设定页内容验证，而不是只检查空工作台。

### 首轮待确认项（评审历史已在补测中复现）

本次得到评价结果后，切到设定页编辑内容，再回质量页显示“尚未评价”，未见旧结果或“内容已变化”的解释。仅凭这条操作链不能区分切页丢失、主动失效或结果未持久化，需要独立复验。

已浏览首页与五个工作台页签，当前未生成正文的阶段未发现全书导出入口。不能据此判定终态没有导出功能；应在有正文和 FINAL 状态分别验证格式、目录、分卷与版本。
