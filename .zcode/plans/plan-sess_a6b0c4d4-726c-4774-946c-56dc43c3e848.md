# 修复方案：大纲延迟生成触发路径错配 + 解析健壮性

## 根因

`tryExtendLayeredOutline` 只在 `runWritingLoop`（L1128）中调用，但异步写作引擎（`WritingTaskExecutor`）逐章调用 `runWritingOneChapter` → `doWriteOneChapter`。当大纲耗尽时，`doWriteOneChapter` 走 `VOLUME_DONE` 终结分支（L402-406），**从不经过 `runWritingLoop` 的大纲耗尽检查**。

## 修复

### 修复1：在 doWriteOneChapter 的大纲耗尽分支中调用 tryExtendLayeredOutline

`doWriteOneChapter` 第 402-406 行，当 synopsis==null 时：
- 当前逻辑：设置 `VOLUME_DONE`，返回 null
- 修复后：先调用 `tryExtendLayeredOutline`，如果成功扩展则重新查找 synopsis 继续写作；失败才走 VOLUME_DONE

### 修复2：parseAndAppendVolume 正则健壮性

当前正则 `第(\d+)章\s*(.+?)：(.+?)(?=第\d+章|$)` 要求冒号分隔，但 LLM 可能输出不同格式。改为更宽松的匹配，并在解析出 0 章时返回 false（而非 true）让上层正确处理。

### 修复3：tryExtendLayeredOutline 解析失败时返回 false

当前 `parseAndAppendVolume` 可能解析出 0 章但仍返回 true，导致循环判断 `hasNextChapter` 仍为 false 后 break。修复为解析出 0 章时返回 false。

## 改动文件

| 文件 | 改动 |
|---|---|
| `NovelOrchestrator.java` | doWriteOneChapter 大纲耗尽分支加 tryExtendLayeredOutline 调用 |
| `NovelOrchestrator.java` | parseAndAppendVolume 返回 int（解析出的章数），0 章时 tryExtendLayeredOutline 返回 false |
