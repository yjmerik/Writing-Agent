# Phase 7: 交互式写作模式 + 可用性增强

## 设计理念

作者通过浏览器界面逐章交互式创作：
1. **写一章 → HTML 呈现 → 审核 → 批准/重写 → 写下一章**
2. 所有控制通过 REST API + 前端界面完成
3. 后端：交互式暂停 + 章节重写 + 名称清理 + 阈值参数化
4. 前端：交互式审核面板（新增 React 组件 + 重新构建）

---

## p7-1: 后端 — 交互式逐章写作 + 章节重写 + 审核端点

### 交互式暂停（INTERACTIVE 模式）

在 `runWritingOneChapter` 末尾：如果 `mode == INTERACTIVE`，创建 `AFTER_CHAPTER` checkpoint，状态设为 `PAUSED_AT_CHECKPOINT`。

### 智能恢复

`resumeFromCheckpoint` 查询最近 PENDING checkpoint 的 type：
- `AFTER_INITIAL_SETUP` → PLANNING
- `AFTER_CHAPTER` → WRITING（继续写下一章）

### 审核端点（新 CheckpointController）

```
POST /api/projects/{id}/checkpoints/{checkpointId}/approve  — 批准
POST /api/projects/{id}/checkpoints/{checkpointId}/reject   — 拒绝（带修改意见重写当前章）
GET  /api/projects/{id}/checkpoints                          — 列出待审核
```

### 章节重写端点

```
POST /api/projects/{id}/rewrite-chapter/{chapterIndex}      — 重写指定章节（不限状态）
```

## p7-3: 前端 — 交互式审核面板

### 新增 InteractiveReview 组件

替换现有只读 ChapterReader，新增交互式审核面板：

**功能：**
1. 章节列表侧边栏（带状态标记：✅已审核 / ⏳待审核 / 🔄重写中）
2. 章节正文阅读区（优化排版，首行缩进，段落间距）
3. 审核操作栏：
   - ✅ 批准并继续 → 调 approve API + write-chapter
   - ❌ 拒绝并重写 → 弹出修改意见输入框 → 调 reject API
   - 📝 修改意见 → 填写具体修改建议
4. 实时状态显示（当前项目状态、checkpoint 信息）
5. 进度追踪（已完成/总计章节、卷进度）

**交互流程（界面操作）：**
```
1. 创建项目（INTERACTIVE模式）
2. 点击"推进状态" → 构思完成 → 暂停
3. 审核设定（世界观/人物/大纲标签页）
4. 点击"批准设定" → 进入写作
5. 点击"写一章" → 第1章完成 → 暂停
6. 在"章节阅读"标签页审核第1章
7. 点击"批准" → 继续写作
8. 或点击"重写" → 输入修改意见 → 重写第1章
9. 重复 5-8 直到全书完成
```
