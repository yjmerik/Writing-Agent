## 发现

### F1（P1）：HIGH 未决时项目可能无 UI 出路（裁决动线断裂）

链路：第 1 章守卫 HIGH（时间标记矛盾）→ 批准被正确阻断（设计）→「拒绝并重写」被
PAUSED 任务占坑阻断（"已有进行中的写作任务"）→「停止当前任务」仅对 BUSY 任务生效
（PAUSED 停不掉）→「从当前进度继续」因待审核禁用。同时后端有完整的裁决机制
（POST /dispositions：FALSE_POSITIVE/EXCEPTION/DEFER + 强制理由 + 版本绑定，
批准门禁认可），质量评价标签的「作为创作例外保留」按钮 tooltip 承诺"记入处置台账，附理由"，
**但点击只做页面跳转，全站不存在裁决提交表单**；`resolve-review` 端点同样无 UI 入口。
结果：真实用户遇到未解决 HIGH + 暂停任务时无法从界面恢复写作。质量评价标签虽有处置按钮组，
动线与审查卡断裂且提交能力缺失。建议：在审查卡/问题行内嵌裁决表单（复用 dispositions API），
并允许 PAUSED 任务被显式终止或被新任务取代。**未修复，登记待办。**

### F2（已修复，合 main `6d3a242`）：模型配置页缺 EXTRACTION 路由

NCS-066 新增的提取路由未加入 `ModelConfigController.SCOPES`（硬编码"默认+8任务类型"），
配置页不可见/不可编辑。先失败测试（断言 10 条+提取任务条目）后修复，全量 1187 绿，
重启实例后 UI 已显示「提取任务 EXTRACTION 16000」。

### F3（P2，登记）：复验动线依赖手动补查

纠偏重写（v3）后检测问题仍显示旧稿 HIGH（过期标记正确），但未自动对新增量复验；
作者需手动「补查当前稿连续性」。与体验报告 P1#3 方向一致，属既有设计，不新增缺陷计数。
